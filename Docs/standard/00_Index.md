This standard is the engineering constitution for the product. It **must be
consulted before every change** — bug fix, hotfix, feature, refactor,
optimization, security patch, dependency/framework update, database migration,
recipe-format change, AI-model or threshold change, dataset/labeling change,
GUI workflow change, camera/lighting/robot/MES/OPC UA/API change,
installer/update change, configuration, logging, authorization, or
customer-specific customization, and any deployment-topology change.
No change is exempt because it is "small," "temporary," "only a PoC,"
"generated by AI," or "urgent" (Executive Engineering Policy, VOL01 §2).

## 4. Machine enforcement of this document

The requirement catalogue is machine-parsed. `Scripts/standard_catalogue.py`
validates every record's grammar, ID uniqueness, and contiguous numbering, and
regenerates the VOL20 §58 index (`catalogue_index.generated.md` +
`requirement-catalogue.json`). It runs in CI as fitness function **FF-STD-01**
(VOL17 §52). Editing the generated index by hand is prohibited.

```
python Scripts/standard_catalogue.py --repo-root . --emit-index --json-out Docs/standard/requirement-catalogue.json
```

## 5. Reading order

- New contributor: VOL01 (policy + change contract) → VOL03 (architecture +
  dependency rules) → VOL06 (coding standard) → VOL17 (gates + Definition of
  Done), then the volume for your subsystem.
- Reviewer rejecting a change: cite the specific requirement ID; the §49
  auto-reject list (VOL17) plus VOL20 §58 index make lookup fast.
- AI coding agent: `AGENTS.md` remains the concise operational contract; it
  points here. Agents receive the subset relevant to their task and may not
  reinterpret or weaken it (VOL17 §48).
